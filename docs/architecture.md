# 구조와 확장 계약

Schale은 SchaleDB 호환 데이터를 매개로 여러 자동화 도구를 조합합니다. 영상에서 읽는 과정과 계정 상태를 이용하는 과정은 독립적입니다.

```text
SchaleDB 정의 ── ReferenceCatalog ── 기준 ID·정의

사이트 export ── adapters.schaledb ─────────┐
영상/이미지 ── students ── adapters.extraction ── AccountSnapshot
향후 다른 입력 ── 해당 어댑터 ─────────────┘       │
                                    collections.compare / merge
                                                   │
                                       adapters.schaledb ── 사이트 export

스테이지·드롭 정의 ── StageRewards ── 보상 기대값
```

## 기준 데이터와 사용자 상태

`ReferenceCatalog`는 학생·아이템·장비·스테이지·가구·그룹 정의를 제공하며 계정의 보유/육성 상태를 뜻하지 않습니다. `entries`는 원본 ID-keyed 형식이고 `get(id)`는 복사본입니다. 지역은 언어 데이터 선택이며 계정 서버 판정이 아닙니다. 그룹 정의는 언어 공통입니다.

카탈로그 `sha256`은 키 정렬·UTF-8·공백 없는 JSON 직렬화의 내용 해시입니다. 들여쓰기에 의존하지 않습니다. 기존 `Extraction.catalog_sha256`은 원본 파일 해시 규칙을 유지하므로 두 종류의 해시를 직접 비교하지 않습니다.

`AccountSnapshot`은 `kind="schale.account"`, `schema_version=1`인 공통 계정 JSON입니다. `StudentState`는 SchaleDB `student_id`, 고유 `key`, 이름, 신원 상태, 육성 필드, 출처, 어댑터 확장 속성을 가집니다. 미확인 학생은 ID=null로 유지할 수 있습니다. 중복 ID·key, 지원하지 않는 필드, 범위 밖 값, 정수 대신 bool 입력은 거부합니다.

19개 필드는 성급, 레벨, 인연, EX/기본/강화/서브 스킬, 전용무기 성급·레벨, 애용품 티어, 장비 세 슬롯의 티어·레벨, 체력·공격·치유 능력 개방입니다. 이름과 현재 유효 범위는 `account.GROWTH_BOUNDS`가 기준입니다. 게임 상한 변경 시 모델·어댑터·테스트를 함께 검토합니다.

각 `GrowthValue`는 값, 상태, 출처를 포함합니다. 영상 근거의 시각·ROI·점수·방법도 보존합니다. 파일을 복사/업로드하지 않으므로 근거 이미지와 원본 추출 폴더를 함께 보관하세요. 공통 계정 파일은 원래 감독 보고서의 대체물이 아닙니다.

## 확인 상태와 병합

| 상태 | 의미 | 기본 병합·내보내기 |
|---|---|---|
| `unknown` | 알 수 없음, null | 보류 |
| `conflict` | 관측 충돌, null | 보류 |
| `observed` | 단일 관측 | 명시적 opt-in만 |
| `inferred` | 규칙으로 추론 | 명시적 opt-in만 |
| `confirmed` | 여러 관측 일치 | 수용 |
| `corrected` | 사람이 교정 | 수용 |
| `imported` | 외부 파일에 명시 | 수용 |

`imported`는 픽셀로 검증했다는 뜻이 아닙니다. 신뢰할 수 있는 사용자의 컬렉션을 입력으로 선택한다는 계약입니다. `confirmed`도 정답 확률이 아닙니다.

`merge(base, incoming)`은 입력을 수정하지 않고 새 스냅샷과 보고서를 반환합니다. incoming의 수용 가능한 값이 우선하며 불확실한 값은 base를 지우지 않습니다. 안 보인 학생을 삭제하지 않습니다. 미확인 신원/필드는 보고서로 보류하므로 원본 incoming 파일을 보관하세요. 자동 시각 비교는 하지 않으며 최신/우선 자료 선택은 호출자의 책임입니다.

동일 값의 근거를 합치고, 관측 수준의 같은 값이 기존 확인 상태를 낮추지 않도록 합니다. `extensions`의 설정은 base 우선으로 빠진 속성만 채웁니다. `compare`의 `missing_ids`는 새 스냅샷에 없는 ID이지 미보유/삭제 판정이 아닙니다. 값과 확인 상태 변화를 함께 비교합니다.

## 외부 형식과 의존성

SchaleDB 짧은 키, base64, `lock`, 최소 스킬 레벨 규칙은 `adapters.schaledb`에만 둡니다. 장비 자체 레벨은 사이트 형식에 없으므로 내부에 보존하고 변환 손실을 명시합니다. 미지의 사이트 속성은 `extensions.schaledb`에 보존합니다. 누락 값을 기본값으로 채우지 않으며 불완전한 신규 레코드는 내보내기에서 제외·보고합니다.

코어는 Pydantic·Requests·Typer·FileLock을 사용합니다. 공통 계정·컬렉션 모듈은 OpenCV·ONNX·학습 모델에 의존하지 않습니다. 비전 입력 어댑터는 결과 모델만 참조하고 인식기를 import하지 않습니다. 영상·이미지 묶음은 입력 계약으로 정규화하고, 모든 SchaleDB 소비자는 공유 HTTP 캐시를 사용합니다. 상세 계약은 [캐시](cache.md), [입력](inputs.md)을 참고하세요. 인벤토리 도구는 선택 기능입니다.

## 도구 추가 기준

1. 입출력 계약을 먼저 정하고 SchaleDB ID를 유지합니다.
2. 새 입력 형식은 어댑터에서 변환합니다. 모든 도구가 계정 모델을 쓸 필요는 없습니다. 보상 계산처럼 정의만 필요한 도구는 직접 조회합니다.
3. 계산은 파일/CLI와 독립적인 함수로 제공하고 CLI는 검증·입출력을 연결합니다.
4. 실제 필요한 공통 개념이 생길 때만 모델을 확장합니다. 학생 모델에 재료나 스테이지 필드를 억지로 넣지 않습니다.
5. 불확실성·변환 손실·출처를 드러내고 실패를 성공값으로 대체하지 않습니다.
6. 성공, 불완전 입력, 데이터 보존, 기존 API, 설치된 배포본 사용을 검증합니다.

런타임 플러그인 시스템·작업 큐·범용 게임 봇 프레임워크는 현재 필요하지 않아 도입하지 않았습니다. 향후 도구는 이 계약 위에 독립 모듈로 추가합니다.
